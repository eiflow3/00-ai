# Governance / PII — test plan

Written before implementation. Each line is one test case. Fixtures referenced
here live in `tests/fixtures/`: `pii_sample.txt`, `pii_sample.md`,
`pii_sample.pdf` (generated by `make_pii_pdf.py`). All PII in the fixtures is
synthetic — reserved test ranges only.

## Detection (`governance/pii/detector.py`)

- Detects each entity type alone in a short string: email, phone (US and PH formats), SSN-shaped ID, credit card, IP address, date of birth, person name, street address.
- Returns correct character offsets when several findings share one paragraph.
- Finds nothing in clean business prose (the "NOT PII" trap sections of the fixtures).
- Does not flag an SSN-shaped substring inside a longer token (`ORD-000-12-3456`).
- Does not flag a four-part version number (`10.4.0.1`) as an IP address.
- Does not flag a part number (`555-0100-A`) as a phone.
- Detects an entity split across a hyphenated/extracted line break (PDF-derived text).
- Deduplicates overlapping matches (an email inside a mailto: URL yields one finding).
- Card number is validated (Luhn) before being reported, not shape-matched only.

## Classification (`governance/pii/classifier.py`)

- Free-mail domain (gmail.com) → classified personal.
- Role address (`hr@`, `info@`, `sales@`) → classified business.
- Named corporate email (`juan.delacruz@acmecorp.example`) → classified ambiguous, resolved by policy default.
- A domain on the own-domain allowlist suppresses or downgrades the finding.
- Context words shift the class: "her personal email" → personal, "our headquarters address" → business.
- A published office address is business; a residential address with a person's name nearby is personal.
- Every finding carries a confidence, and policy thresholds are applied to it.

## Actions (`governance/pii/actions.py`)

- Mask replaces the value with its type token (`[EMAIL]`) and changes nothing else — byte-identical text outside the span.
- Pseudonymize is stable: the same raw value yields the same placeholder across chunks and across documents.
- Tag-and-keep leaves the text untouched and attaches finding metadata to the chunk.
- Reject stops the document: nothing is chunked or embedded, and the run records the rejection reason.

## Policy and knobs (`governance/policy.py`)

- Precedence resolves request override > per-source policy > global default.
- `mode=off`: no detector executes (no detection cost), and the run is stamped unscreened.
- `mode=audit_only`: findings are recorded and the stored/embedded content is byte-identical to the input.
- `mode=enforce`: the configured action is applied per finding class.
- Ingest mode and chat mode are independent — governance off at ingest does not disable chat-time stages.
- Verbatim knob `off`: no raw matched string appears anywhere in the audit record or logs.
- Verbatim knob `preview`: audit holds a masked excerpt (`j***@ac***.example`), never the full value.
- Verbatim knob `full`: raw value stored, and the record is stamped with the mode it was written under.
- Verbatim knob is config/source-level only — a request body cannot switch it.
- Purge action strips raw values from past `full` records but keeps type + location.

## Runner (`governance/runner.py`)

- Runs the enabled stages in configured order and emits a stage start/end pair per stage.
- Fail-closed: a detector exception under `enforce` halts the pipeline rather than passing content through.
- A detector exception under `audit_only` logs the error and lets content proceed (screening was advisory).
- A skipped stage (mode off) still appears in the timeline marked skipped.
- Stage duration is recorded per run.

## Ingest integration

- Redaction happens before chunking: no chunk sent to the vector store contains the raw value (assert against the fake vector client from the existing test seam).
- Chunk metadata carries governance mode and tags only through the provenance service.
- Re-ingesting the same document with pseudonymize does not produce a second placeholder for the same value.
- PDF fixture: findings on the derived markdown map back to the correct page number.
- PDF fixture: the phone number split across the page 2→3 break is still detected once.
- Table cells in the PDF and markdown fixtures are scanned, not just prose.

## Chat integration

- Inbound `enforce`: a pasted SSN is masked before the retrieval query and the LLM call are made.
- Inbound `reject`: the stream ends with a terminal policy-block event, and no LLM call happens.
- Retrieval filter: chunks tagged personal-PII are excluded from the prompt context when the request policy says so.
- Outbound: an answer containing indexed PII is masked before it streams to the client.
- Governance stages appear as `stage` SSE events with their own names; existing clients need no changes.
- No SSE event payload ever contains a raw detected value.
- The policy-block event is distinguishable from the existing `error` event.
- New event schemas exist in `schemas/` and the chat docs module is updated in the same change.

## Audit and logging

- Every finding produces one audit record via `run_store`: type, location, classification, confidence, action, mode.
- Log lines carry counts and entity types only — a grep for any fixture raw value over captured logs finds nothing.
- The audit record answers "what did we catch in this document and what did we do" for a whole run.
