# Question: What is the better way to convert a pipeline into text description without over complexity?

## Answer
The best way to convert a complex technical pipeline into a readable text description is to:
1. **Divide into Logical Phases:** Group the steps into overarching stages (e.g., "Preparation Phase" vs. "Execution Phase").
2. **Use Clear, Sequential Lists:** Use numbered lists or bullet points to walk through the pipeline step-by-step.
3. **Focus on Inputs and Outputs:** For each step, briefly mention what goes in and what comes out, avoiding overly dense jargon.
4. **Keep it Action-Oriented:** Start each step with a clear action verb (e.g., "Chunking: Break the large documents down...").

*Note: For an applied example of this, see the traditional RAG pipeline description in `/data/00-traditional-rag.txt` and `/docs/traditional-rag-overview.md`.*
